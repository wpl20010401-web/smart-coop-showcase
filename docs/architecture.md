# 系统架构（概览）

> 本页只描述设计思路，不包含实现细节与源码。完整代码为私有仓库。

## 1. 四层结构

```text
场景与数据层
  合作社 / 田块 / 农机 / 无人机 / 天气
        │
        ▼
仿真环境层
  作业推进 · 转场 · 故障 · 加油换电 · 灾害 · 倒伏
        │
        ├── 全局分配（GAVNS）
        └── 多智能体决策（全局 / 农机 / 无人机 / 气象）
        │
        ▼
指标层
  收割率 · 协同得分 · 数据质量 · 效率因子
        │
        ▼
展示层
  数字孪生看板：地图态势 · 天气矩阵 · 告警 · 设备状态
```

## 2. 为什么这样设计

**无人机要进调度闭环，而不是只做巡检。**
如果无人机只负责拍照，它产生的信息无法改变调度；把它定义成“感知节点”，巡检结果才能触发农机重分配、异常确认和应急侦察。

**两层决策：全局分配 + 局部调整。**
GAVNS 负责“哪台机器去哪个田块”的组合优化，适合静态或半静态分配；多智能体策略负责“每一步怎么走”的动态调整，适合天气和灾害带来的扰动。两层分开，既能解释，也能评估各自的增益。

**倒伏要影响效率，而不是只影响显示。**
倒伏等级会折减收割速度，无人机支援可以部分缓解。这样“无人机协同”的价值才能被量化，而不是停留在概念上。

**天气默认用模拟引擎。**
保证任何人拿到代码都能离线复现；实时天气作为可选能力，失败时自动降级，不阻塞实验。

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| 收割完成率 | 已收割面积 / 总作业面积 |
| 协同得分 | 无人机与农机在时间、空间上的配合程度 |
| 数据质量 | 无人机覆盖带来的信息增益 |
| 效率因子 | 倒伏与无人机支援共同作用后的平均作业效率 |

## 4. 实验设计

四组对照：传统模式（无无人机）、仅调度（无无人机）、巡检消融（普通巡检）、智慧协同（协同任务 + 倒伏闭环），外加极端天气压力测试。核心变量是“无人机是否参与协同”和“天气扰动强度”。

## 5. 边界

- 结果是仿真结果，用于比较机制差异，不代表真实地块的绝对产量；
- 案例覆盖河南 25 个区县的地理与合作社结构，外推需谨慎；
- 历史随机种子未保存，重跑不会逐位复现，但趋势与量级稳定。
